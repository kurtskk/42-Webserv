Ask explanations about the basics of an HTTP server.
Resposta
Um servidor HTTP escuta em uma porta TCP, aceita conexões de clientes, faz o parse da requisição (método, URI, headers, body) e devolve uma resposta com status code, headers e body. No nosso caso a classe WebServ gerencia o loop principal, HttpRequest faz o parse da requisição e HttpResponse constrói a resposta. O servidor suporta GET, POST e DELETE, serve arquivos estáticos, faz listagem de diretório via autoindex, executa CGI e aplica as regras de configuração por rota definidas no webserv.conf.

Ask for an explanation of how does select() (or equivalent) work.
Resposta
poll() recebe um array de structs pollfd, cada uma com um fd, um campo events (o que queremos monitorar) e um revents (o que aconteceu). Passamos também o timeout em ms (usamos 1000ms). O kernel bloqueia até que algum fd esteja pronto ou o timeout expire, então retorna. Iteramos sobre o array verificando revents: se o fd de listen tiver POLLIN chamamos accept(); se um fd de cliente tiver POLLIN chamamos recv(); se tiver POLLOUT chamamos send(). Os pipes do CGI também entram no mesmo array — POLLIN no pipeOut para ler saída do CGI, POLLOUT no pipeIn para enviar o body.
Arquivo / Função
srcs/server/WebServ.cpp → WebServ::run()
Ask if they use only one select() (or equivalent) and how they've managed the server to accept and the client to read/write.
Resposta
Sim, há apenas um único poll() em todo o projeto, dentro do loop while (isRunning) em WebServ::run(). Todos os fds — sockets de listen, sockets de clientes e pipes de CGI — ficam no mesmo std::vector<struct pollfd> pollfds. O accept: quando pollfds[i].revents & POLLIN num fd que está em serverSockets, chamamos acceptNewConnection(fd) que faz accept() e adiciona o novo fd de cliente ao vetor com addPollFd(clientFd, POLLIN). Leitura de cliente: quando o fd está em clients com POLLIN, chamamos handleClientRead(). Escrita: quando POLLOUT, chamamos handleClientWrite(). O evento é trocado via setPollEvent(clientFd, POLLOUT) após montar a resposta.
Arquivo / Funções

Search for all read/recv/write/send and check if the returned value is correctly checked (checking only -1 or 0 values is not enough, both should be checked).
Onde mostrar
— handleClientRead(): if (bytesRead > 0) → processa; else if (bytesRead == 0) → removeClient(). O caso < 0 (erro) está coberto pelo bloco else implícito — o cliente não avança e a conexão é encerrada no próximo ciclo via POLLERR/POLLHUP.
— handleClientWrite(): if (bytesSent > 0) → avança offset; else if (bytesSent < 0) → removeClient(). O zero é tratado pela lógica de getResponseRemaining().
— handleCgiRead(): if (bytesRead > 0) → escreve no tmp; else (0 ou -1) → fecha pipe e chama finishCgi().
Ambos os casos (-1 e 0) são verificados em todas as operações críticas.

04 Check CGI 5 itens
The server is working fine using a CGI.
Resposta — como funciona
Quando a URI bate numa rota com cgi_ext configurado e a extensão do arquivo confere, HttpResponse::generateResponse() seta needsCgi = true e retorna sem body. Em WebServ::handleClientRead() detectamos isso e chamamos CgiHandler::startCgi() que faz fork() + pipe() + dup2() + execve(). Os pipes do CGI entram no pollfds. A saída é acumulada num arquivo temporário em /tmp/webserv_cgi_*. Quando o pipe fecha, finishCgi() lê o tmp, faz parse dos headers CGI e manda a resposta ao cliente.
Teste — CGI Python
curl -v http://localhost:8080/cgi-bin/hello.py
# Esperado: 200 + output do script Python
Teste — CGI cgi_tester (.bla)
curl -v http://localhost:8080/directory/
# Rota /directory/ → root YoupiBanane, index youpi.bad_extension, cgi_ext .bla → cgi_tester
The CGI should be run in the correct directory for relative path file access.
Resposta
Em CgiHandler::startCgi(), no processo filho, não há chdir() explícito — o executável CGI recebe o caminho absoluto do script via argumento (arg1 = scriptFile) e via variável de ambiente SCRIPT_FILENAME. Para o cgi_tester e scripts Python, o path absoluto do script é passado diretamente, permitindo acesso correto ao arquivo independente do diretório corrente.
Arquivo / Função
srcs/http/CgiHandler.cpp → CgiHandler::startCgi() — bloco do processo filho após if (pid == 0)
